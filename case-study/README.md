# Case study captures

Every image here is generated by `npm run capture` (`scripts/capture-case-study.ts`, Playwright with the system Chrome). Before starting, the script:
- resets the demo data from Settings → Data → "Reset demo data"
- checks that the demo clock (Oct 16, 2026, 10:00) is on, so every run is identical

Viewport: 390×844 at @2x. Visual system: [Marginalia](../docs/visual-system.md), on theme v2 ("Goodreads 1": indigo on stone; Plus Jakarta Sans for titles and numbers, Playfair Display SemiBold Italic only for the book hero title and the share cards). Persona and hypotheses: [design context](../docs/design-context.md).

**70 PNGs:** 46 screens (23 light + 23 dark), 19 flow steps plus the F4 export, and 4 share cards.

## Audits: `audit.json`

All 37 screens pass (light). Each one is checked for:
- **Touch targets ≥ 44×44px**, counting `::after` hit-area extensions. Stretched card links, inline text links and switch/checkbox label rows are measured by their row.
- **No nested interactive elements** (`a a`, `a button`, `button a`, `button button`, `a input`, `button input`).
- **No horizontal overflow** (`scrollWidth − clientWidth`).
- **Text contrast as rendered** (light and dark): each text node's color against its composited ancestor backgrounds, 4.5:1, or 3:1 for large text. Disabled controls are skipped (WCAG exempts them).

Screens audited:
- The 23 case-study screens above (in light and in dark for contrast).
- Visitor profile, Edit profile, Settings, Buddy reads tab, Groups tab, a group, a thread, Messages, Find friends, Invite, 404 and `/dev/components`.
- Library in list view and in selection mode.

What the audit caught:
- A horizontal overflow on Home, where an `sr-only` span in the carousel escaped its scroller. It's fixed, and every horizontal scroller is now `relative`.
- Theme v2: avatar initials on `--muted` in `--muted-foreground` (3.92:1). The avatar fallback now uses the stone `--secondary` pair (5.07:1).

Other checks done outside this script:
- 103 Vitest tests pass, including one that checks every cover is a self-hosted file and two for the challenge card (ink bar, "Raise your goal").
- With `prefers-reduced-motion: reduce`, no animation runs.
- Every state is told by more than color (weight, fill, icon or a word).
- Covers on a first, cold visit: 0 still gray 1.5 s after load on Library (Reading, Want to read) and Profile, down from 2, 3 and 4. They used to go through two Open Library redirects to archive.org; they're now served from `public/covers/`.

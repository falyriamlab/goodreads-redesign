# Case study captures

Every image here is generated by `npm run capture` (`scripts/capture-case-study.ts`, Playwright with the system Chrome). Before starting, the script:
- resets the demo data from Settings → Data → "Reset demo data"
- checks that the demo clock (Oct 16, 2026, 10:00) is on, so every run is identical

Viewport: 390×844 at @2x. Visual system: [Marginalia](../docs/visual-system.md). Persona and hypotheses: [design context](../docs/design-context.md).

**70 PNGs:** 46 screens (23 light + 23 dark), 19 flow steps plus the F4 export, and 4 share cards.

## Audits: `audit.json`

All 37 screens pass (light). Each one is checked for:
- **Touch targets ≥ 44×44px**, counting `::after` hit-area extensions. Stretched card links, inline text links and switch/checkbox label rows are measured by their row.
- **No nested interactive elements** (`a a`, `a button`, `button a`, `button button`, `a input`, `button input`).
- **No horizontal overflow** (`scrollWidth − clientWidth`).

Screens audited:
- The 23 case-study screens above.
- Visitor profile, Edit profile, Settings, Buddy reads tab, Groups tab, a group, a thread, Messages, Find friends, Invite, 404 and `/dev/components`.
- Library in list view and in selection mode.

The audit also caught one real bug: a horizontal overflow on Home, where an `sr-only` span in the carousel escaped its scroller. It's fixed, and every horizontal scroller is now `relative`.

Other checks done outside this script:
- 98 Vitest tests pass.
- With `prefers-reduced-motion: reduce`, no animation runs.
- Every state is told by more than color (weight, fill, icon or a word).
